# T06 — Test 1: dimension chain closure

**Depends on:** T02 (schema) · **Parallel with:** T07

## Goal

Implement `tests/test_chains.py`. Highest-value, cheapest check in the suite. Requires no
geometry — it runs on the raw spec, so it can be built and tested against a fixture
before T04/T05 finish transcribing.

## What to implement

### 1. Closure

Every chain's segments must sum exactly to its printed total:

```python
def test_chain_closure(spec):
    for chain in spec["dimension_chains"]:
        assert sum(chain["segments_cm"]) == chain["total_cm"], (
            f"{chain['id']} ({chain['source_image']}): "
            f"segments sum to {sum(chain['segments_cm'])}, "
            f"printed total {chain['total_cm']} (cm)"
        )
```

Integers mean **exact equality — no tolerance**. Do not add one. Chains are stored in
**centimetres**, verbatim as printed; assert on the cm values before conversion.

### 2a. Magnitude sanity — the check chain closure cannot do

Chain closure is invariant to scale: a spec transcribed in centimetres but interpreted as
millimetres closes perfectly and describes a house one tenth the size. This is the single
scale error the rest of the suite will not catch, so assert magnitudes explicitly:

- Overall building dimensions: **5 000 – 50 000 mm**
- Storey clear heights: **2 000 – 4 000 mm**
- Individual room dimensions: **500 – 20 000 mm**
- Wall thicknesses: **80 – 600 mm**

Expected values for cross-reference: the building is **17.10 × 9.00 m**; ground floor
clear height 2.70 m, attic 2.73 m. Assert the overall dimensions against 17 100 × 9 000 mm
directly — T03 confirmed these from two independent chains plus the site plan.

### 3. Cross-chain consistency

Chains running along the same axis across the same extent must agree with each other.
A plan typically prints an outer overall chain plus one or more inner chains; they are
redundant by construction and that redundancy is free error detection.

Group chains by `(level, axis)` and assert all totals spanning the same extent match.
Where chains span different extents, this check is skipped — report how many chains were
actually cross-checked, since a chain with no partner is unverified by this test.

### 4. Chain-to-geometry agreement

Once walls exist, assert that wall coordinates derived from a chain actually reproduce
that chain's segment lengths. This closes the loop between "the numbers I typed" and
"the geometry I built from them", catching arithmetic slips during coordinate derivation.

Skip gracefully (`pytest.skip`) if walls are not yet present, so this task can land
before T04/T05.

## Failure message quality matters

This test is the project's first line of defence and will fire during active
transcription. Make failures name the chain id, the source image, both numbers, and the
delta — an agent fixing a typo should not have to open the plan to know where to look.

Include the delta explicitly: a delta of e.g. 900 or 1000 usually means a whole missing
segment, while 10 or 100 usually means a digit misread.

## Acceptance criteria

- All four checks implemented, including magnitude sanity
- A spec with every chain scaled by 1/10 fails the magnitude check
- Unit-tested against synthetic fixtures: a closing chain passes; an off-by-100 chain
  fails with a message naming the chain and the delta; disagreeing cross-chains fail
- Test skips cleanly when run against a spec with chains but no walls
