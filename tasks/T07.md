# T07 — Geometry kernel (2D)

**Depends on:** T02 (schema) · **Parallel with:** T06

## Goal

`src/kotewki/geometry.py` — turn the spec's wall centrelines into real 2D geometry, and
compute room polygons and areas. This is the foundation for T08, T09, T10, T11 and T13;
every dimensional claim the project makes routes through this module.

## What to implement

### Wall solids (2D footprints)

Buffer each wall centreline by `thickness/2` to a rectangle. Join adjacent walls at
corners and T-junctions cleanly — mitred at corners, no overshoot at tees. Use
`shapely.buffer(..., cap_style="flat", join_style="mitre")` and then union the network.

Wall layers matter: an exterior wall is Porotherm 250 + EPS 200 + plaster. Model it as a
**layered wall with individually addressable faces**, not a single 465 mm slab. T15 needs
to switch which face rooms are measured to; that switch must be a parameter, not a
rewrite.

### Room polygons

Given a room's bounding wall ids, produce the enclosed polygon. Two viable strategies —
implement the second:

1. Intersect half-planes from each bounding wall — brittle at non-convex rooms
2. **Polygonise the wall network** (`shapely.ops.polygonize`) and select the face
   containing the room's seed point — robust, handles L-shaped rooms

This means rooms need a seed point. Either add an optional `seed: [x, y]` to the schema
(coordinate with T02) or compute it as the centroid of the naive boundary and validate it
falls inside exactly one face.

### The measurement-face parameter — most important design decision here

```python
def room_polygon(spec, room_id, *, measure_to: Literal["structure", "finish"]) -> Polygon
```

- `"structure"` — inner face of the Porotherm block
- `"finish"` — inner face of the plaster (≈10–15 mm thinner per side)

**Do not hardcode either.** T15 resolves which one reproduces Archon's published areas,
and T08 must be able to run both to diagnose a uniform offset. Making this a parameter is
the difference between a 10-minute diagnosis and a day of chasing phantom geometry bugs.

### Quantities → `src/kotewki/quantities.py`

- `room_area(room, measure_to)` → m²
- `footprint_polygon(level)` → outer envelope, for the 154.42 m² check
- `usable_area(level, include_stairs: bool)` → respects the stairs inclusion rule
- `usable_area_sloped(polygon, roof, floor_elevation)` → the attic height-banding rule
  (**< 1.4 m = 0%, 1.4–2.2 m = 50%, > 2.2 m = 100%**). Coordinate with T05, which specifies it.

## Precision

Spec is integer millimetres. Convert to metres **once**, at the boundary into shapely, and
work in metres inside. Do not round intermediate results — areas compare at ±1%, which is
far looser than float error, so precision loss is not a real risk, but silent rounding is.

## Acceptance criteria

- Unit tests on synthetic geometry with hand-computed answers: a single rectangular room,
  an L-shaped room, a room bounded by walls of differing thickness
- `measure_to` demonstrably changes computed area in the expected direction and magnitude
- Polygonisation handles a non-convex room correctly
- No test depends on the real spec — this module must be testable before T04 lands
