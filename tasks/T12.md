# T12 — glTF export + Test 5: mesh checks

**Depends on:** T11 (generator) · **Parallel with:** T13, T14

## Goal

`src/kotewki/export.py` → `build/model.glb`, plus `tests/test_export.py` verifying the
**artifact** rather than the intent.

## Why a separate test layer

T07–T10 validate the spec and the 2D geometry. T11 validates nothing by itself. Between
"correct scene in memory" and "correct file in the browser" sit unit-scale bugs, exporter
transforms, and mesh corruption — all of which are invisible to every upstream test. This
task closes that gap.

## Export

glTF/GLB via trimesh. Convert millimetres → metres **here and only here**; this is the
single unit boundary in the codebase.

**glTF is defined in metres (1 unit = 1 m).** Emit no scene-level scale transform. This
eliminates the entire "model is 1000× too big" bug class that plagues hand-modelled
architectural assets.

Also emit `build/quantities.json` alongside the mesh — computed areas, volumes, ridge
height — so the viewer can display them and CI can archive them per build.

## Checks to implement

```python
def test_exported_mesh(glb_path):
    scene = trimesh.load(glb_path)
    bbox = scene.bounding_box.extents
    assert np.allclose(bbox[:2], EXPECTED_FOOTPRINT_M, atol=0.01)
    assert np.isclose(bbox[2], 7.09, atol=0.01)
```

Plus:

- **Unit scale is 1.0** — no root scale transform in the glTF node hierarchy
- **Round-trip stability** — export → load → bounding box unchanged. Catches exporter
  scaling bugs, which are otherwise silent.
- Mesh is watertight per component
- No degenerate faces (zero-area triangles)
- No NaN or infinite vertices
- Vertex count is within a sane band (a 10× jump between builds signals a boolean blowup)
- Node names from T11 survived the export — the viewer depends on them

## Bounding box subtlety

The bbox Z extent is ground → ridge = 7.09 m only if the model's origin is at finished
ground level and the roof is the topmost geometry. Confirm both. If a chimney or plinth
extends the bbox, assert against the roof node's bbox specifically rather than the whole
scene, and document why.

The bbox XY extent is the **building** overall dimension including eave overhangs if the
roof is in the scene — so `EXPECTED_FOOTPRINT_M` must come from T04's transcribed
building dimensions plus overhangs, **not** from the 25.1 × 17.0 m figure, which is the
minimum plot size and not a building dimension at all.

## Acceptance criteria

- `just build` produces `build/model.glb` and `build/quantities.json`
- All checks above implemented and passing
- GLB loads without warnings in a stock three.js `GLTFLoader`
- File size reported; flag if over ~20 MB (T14 will need to care)
