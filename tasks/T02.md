# T02 — Spec JSON Schema

**Depends on:** nothing · **Parallel with:** T01, T03

## Goal

Define `spec/schema.json` — the contract that every downstream task reads and writes
against. This is the most load-bearing artifact in the project; get it right before
transcription starts.

## Spec file layout

The spec is **split across three files** so that T04 and T05 can be written by different
agents concurrently without write contention, and so each transcription is independently
reviewable:

```
spec/meta.json      ← owned by T02: levels, roof, construction, meta
spec/ground.json    ← owned by T04: walls/openings/rooms/chains for level "ground"
spec/attic.json     ← owned by T05: walls/openings/rooms/chains for level "attic"
```

`src/kotewki/spec.py` merges the three into one validated in-memory spec. **No task other
than the listed owner writes to a given file.**

Ids must be globally unique across files — prefix them by level (`G_W1`, `A_W1`) so the
merge cannot silently collide. Make the loader assert uniqueness rather than
last-write-wins.

## Deliverables

`spec/schema.json` (JSON Schema draft 2020-12) covering the merged document:

```jsonc
{
  "meta":    { "source_url", "variant": "E", "transcribed_by", "date" },
  "levels":  [ { "id", "elevation", "ceiling_height", "derived": bool } ],
  "walls":   [ { "id", "level", "start": [x,y], "end": [x,y],
                 "thickness", "type": "exterior|partition|structural",
                 "layers": [ { "material", "thickness" } ] } ],
  "openings":[ { "id", "wall", "offset", "width", "height", "sill",
                 "kind": "window|door|passage", "swing": "left|right|none" } ],
  "rooms":   [ { "id", "name", "level", "boundary": ["W1","W4",...],
                 "published_area": 30.57 } ],
  "roof":    { "pitch_deg": 35.0, "eaves_overhang", "type": "gable",
               "derived_fields": ["eaves_overhang"] },
  "dimension_chains": [ { "id", "level", "axis": "x|y",
                          "segments_cm": [int,...], "total_cm": int,
                          "source_image", "note" } ]
}
```

## Hard schema constraints

- **Every length is `"type": "integer"` — millimetres.** Reject floats at schema level.
  The only floats permitted anywhere are `published_area` / `floor_area_m2` (m², as
  printed) and `pitch_deg`.
- **Dimension chains are the one exception: they are stored in CENTIMETRES**, verbatim as
  printed on the plans, in fields suffixed `_cm`. The loader multiplies by 10. This keeps
  transcription arithmetic-free and confines the ×10 to a single place in the codebase.
  The `_cm` suffix is mandatory so no reader can mistake the unit — see "Units" in
  `README.md` for why a missed ×10 is the one scale error chain closure cannot catch.
- `rooms[].floor_area_m2` — optional. The parenthesised figure on the plans
  (`30,57 (33,2) m²`) is *powierzchnia podłóg*, raw floor area ignoring ceiling height.
  Where printed, it is a **second independent area constraint per room** and T08 asserts
  it separately. Free extra equations; capture them.
- `derived: true` is **required** on any value not transcribed from a printed number.
  Add a schema-level `description` on the field making this explicit.
- `rooms[].published_area` is **required**, not optional. A room with no published area
  cannot be checked, and the schema should make that impossible to create silently.
- `dimension_chains[].source_image` is required — every chain must be traceable back to
  the plan it came from, for dispute resolution during T15.

## Also deliver

- `src/kotewki/spec.py` — loader that merges `meta.json` + `ground.json` + `attic.json`,
  validates the merged result against the schema, and raises on violation. Downstream code
  must never see an unvalidated spec. Tolerate a missing `ground.json`/`attic.json` during
  early development (T06–T14 build against fixtures before transcription lands) — warn,
  do not crash.
- `spec/meta.json` — populated with levels, roof, and construction from `README.md`.
- Empty-but-valid `spec/ground.json` and `spec/attic.json` stubs, so T04 and T05 each have
  a file to fill rather than a schema to re-infer.
- `tests/test_schema.py` — schema self-tests: a minimal valid spec loads; a float length
  is rejected; a room without `published_area` is rejected; an opening referencing a
  nonexistent wall id is rejected; a duplicate id across ground/attic is rejected.

## Acceptance criteria

- Schema validates a hand-written minimal 4-wall 1-room example
- Three-file merge works, and id collision across files raises
- All five negative cases above raise
- `spec.py` loader exposes typed access used by T06, T07, T10
