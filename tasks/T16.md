# T16 — CI wiring & build pipeline

**Depends on:** T06, T08–T13 (all validators)

## Goal

Wire the whole thing into a single reproducible pipeline so that "the model is verified"
is a fact checked by machine on every change, not a claim someone remembers making once.

## Pipeline

```
just build   →  spec → validate → generate → export → overlay
just test    →  the full suite, fail-fast in cost order
just validate →  validators only, no 3D generation (fast inner loop)
```

## Test ordering — fail fast, cheapest and most localising first

```
1. schema validation           (T02)   — instant
2. dimension chain closure     (T06)   — instant, no geometry
3. topology & sanity           (T10)   — <1s
4. room areas                  (T08)   — seconds
5. global invariants           (T09)   — needs 3D
6. exported mesh               (T12)   — needs export
7. orthographic overlay        (T13)   — slowest, needs render
```

This order is deliberate: it is roughly cost-ascending *and* diagnostic-value-descending.
A chain-closure failure tells you exactly which number is wrong; an overlay failure tells
you only that something is off somewhere. Surfacing the former first saves real time.

## CI — local only

> **Changed 2026-08-31 by user decision: the repository stays local.** No remote, no
> GitHub Actions. `data/source/` holds Archon's copyrighted plan bitmaps, so publishing the
> repo would redistribute them.

Wire the equivalent guarantees locally instead. The point of CI here was never the hosting
— it was that "the model is verified" gets re-checked mechanically rather than remembered:

- **`just check`** — `ruff check` plus the full suite in the fail-fast order above. One
  command, exit code is the verdict.
- **A `pre-commit` git hook** (checked in under `hooks/` with a `just install-hooks` target,
  since `.git/hooks/` is not itself version-controlled) running `just validate`. Use the
  fast validator subset, not the full suite — a hook slow enough to be annoying gets
  bypassed with `--no-verify`, and a bypassed hook guards nothing.
- **Keep `build/` artifacts on failure, not just success.** `build/overlay_*.png` is the
  primary debugging aid for a failed overlay test, and deleting it on failure removes the
  evidence exactly when it is needed. Make sure `just build` does not wipe prior output
  before it has succeeded.

If the repo ever does get a remote, the Actions workflow is a thin wrapper over `just check`
— write the recipes so that stays true, but do not add `.github/` now.

## Validation report

`just report` → `build/REPORT.md`, generated, containing:

- Every published figure vs computed, with delta and pass/fail
- The full per-room area table
- Count of transcribed vs `derived: true` values, with every derived value listed
  alongside its justification
- Resolved measurement norm (T15) and any residual ambiguity
- The overlay images

**End the report with the honest limitation**, stated in full rather than gestured at:

> This suite guarantees that the model matches the transcribed spec, and that the spec is
> internally consistent and agrees with every published figure from Archon. It does not
> guarantee that a printed dimension was read correctly in the case where the wrong value
> happens to satisfy every chain sum, every area assertion, and every global invariant
> simultaneously. Redundancy is the defence, not proof. The model is also a reconstruction
> of the *design*, not of any *as-built* house — real construction deviates from drawings.

Do not let this report claim the model is provably correct. It is well-evidenced, which is
a different and honest thing.

## Acceptance criteria

- `just build`, `just test`, `just validate`, `just check`, `just report` all work from a
  clean checkout
- `just install-hooks` installs a working pre-commit hook; committing a spec that breaks a
  validator is blocked by it
- `build/` artifacts survive a failing run
- `build/REPORT.md` generated and includes the limitation statement verbatim
- `just check` runs in under 5 minutes
