# T14 — three.js browser viewer

**Depends on:** T12 (GLB export) · **Parallel with:** T13

## Goal

`viewer/` — a browser view of `build/model.glb`. This is the user-facing deliverable; the
entire validation apparatus exists so that what renders here is trustworthy.

## Stack

Plain **three.js** with `GLTFLoader`, Vite for dev/build. Not `<model-viewer>` — that
gives orbit-only, and a house model is much more useful walkable from the inside.

No framework needed. Keep it a single static bundle that can be opened from a file server
or dropped on any static host.

## Features

**Camera modes — both:**
- Orbit (`OrbitControls`) for exterior massing review
- First-person walkthrough (`PointerLockControls`) with collision against wall meshes and
  a fixed eye height of ~1.65 m. This is what makes the model useful for judging whether
  rooms actually feel right at their stated areas.

**Layer toggles**, driven by T11's node naming: roof on/off, attic on/off, per-level
isolation. Roof-off top-down is the fastest way for a human to sanity-check layout.

**Measurement tool** — click two points, display the distance in metres. This is the
human's escape hatch: it lets anyone spot-check any dimension against the plans without
running the test suite. Worth the effort; it is how non-technical stakeholders will
verify the thing.

**Quantities panel** — read `build/quantities.json` and display computed vs published
areas side by side, with the delta. Putting the validation results *in the viewer* means
the model always ships with its own evidence.

## Rendering

Keep it honest and readable rather than photoreal:

- Neutral materials, no invented textures — this model represents *documented geometry*,
  and photoreal cladding invites people to treat undocumented choices as fact
- Soft ambient + directional light with shadows for form legibility
- Sensible near/far planes for a ~20 m building; a too-far near plane causes z-fighting
  on the thin plaster layers

## Performance

Target 60 fps on a laptop. If the GLB exceeds ~20 MB (T12 reports this), apply Draco or
meshopt compression at export rather than simplifying geometry — geometric simplification
would break the dimensional guarantee that the whole project is built on.

## Acceptance criteria

- `just viewer` serves the app locally
- GLB loads, both camera modes work, walkthrough has collision
- Layer toggles work against T11's node names
- Measurement tool returns correct distances (spot-check against a known room dimension)
- Quantities panel shows computed vs published with deltas
- Runs at 60 fps on a mid-range laptop
