# T11 — 3D generator

**Depends on:** T07 (geometry kernel)

## Goal

`src/kotewki/generator.py` — extrude the validated 2D geometry into a 3D solid model.
Pure function: `spec → trimesh.Scene`. No hand-authored geometry anywhere.

## What to build

### Walls

Extrude each wall footprint from its level elevation to `elevation + ceiling_height`
(plus slab thickness where appropriate). Emit **layered walls** as separate solids where
the layer split matters visually — Porotherm core, EPS, plaster — or at minimum keep the
layer offsets addressable so the exterior render shows correct wall depth at window reveals.
Window reveals are the most visible tell of a wall modelled as a single thin slab.

### Openings — boolean subtraction

Cut windows and doors as box subtractions from the wall solids. Use `manifold3d` via
trimesh for the booleans (see T01 for why not build123d).

Subtract **all openings from a wall in one batched boolean**, not sequentially. Sequential
booleans on the same solid accumulate numerical degradation and are markedly slower.

### Floors and slabs

Reinforced concrete slab between ground floor and attic, per the spec sheet. Ground slab
at the plinth elevation.

### Roof — generative, from pitch

> **UNBLOCKED.** T17 resolved the roof — see `docs/roof-resolution.md` and the "RESOLVED"
> section of `README.md`. The published **35.0°** is correct; the earlier apparent
> discrepancy was a mislabelling of the +2.88 section mark on our side.
>
> Build exactly this chain, taking all values from `spec/meta.json`:
>
> ```
> springing = attic_floor 3040 + knee_wall 290 + roof_buildup_vertical 280 = 3610 mm
> ridge     = springing + (span/2)·tan(pitch_deg)                          = 6761 mm
> ```
>
> `roof_buildup_vertical` (280 mm, at the wall face) and `fascia_depth` (310 mm, at the
> overhang edge) are **different quantities** — conflating them is what produced the
> phantom discrepancy in the first place. Eaves overhang 600 mm, verge overhang 590 mm.

This is the part most likely to be built wrong. Construct it as:

```
eaves line (footprint offset outward by eaves_overhang)
  → rise at pitch_deg (35.0°, exact)
    → planes intersect at ridge
      → ridge height is an OUTPUT
```

**Never position the ridge to hit 7.09 m.** T09 asserts the computed ridge against
7.09 m, and that assertion is only meaningful if the ridge is derived. Forcing it makes
the test a tautology and silently removes the project's only roof check.

Gable ends: fill the triangular wall sections between the wall plate and the roof planes.

### Determinism

Same spec in → byte-identical mesh out. No random seeds, no dict-ordering dependence, no
timestamps in the scene. T13's golden-image diffing depends on this; non-determinism here
turns the overlay test into a flaky test.

## Scene organisation

Name and group nodes so the viewer (T14) can toggle them:

- Per level: `ground`, `attic`
- Per category: `walls`, `slabs`, `roof`, `openings/windows`, `openings/doors`
- Per room, for the walkthrough labels

Preserve room names as node metadata — T14 uses them for labelling and T13 for debugging.

## Acceptance criteria

- `spec → Scene` is a pure, deterministic function
- Meshes are watertight per component (T12 asserts this on the export)
- Roof ridge height is computed and exposed as `scene.metadata["ridge_height_m"]`
- Changing `pitch_deg` changes the ridge height (regression test against tautology)
- Node naming supports the T14 layer toggles
