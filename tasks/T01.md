# T01 — Repo scaffold & tooling

**Depends on:** nothing · **Parallel with:** T02, T03

## Goal

Stand up the Python project so every downstream task has a working `pytest` and a place
to put code.

## Deliverables

- `pyproject.toml` — Python ≥3.11, managed with `uv`
- Dependencies: `shapely`, `trimesh`, `manifold3d`, `numpy`, `pygltflib`, `jsonschema`,
  `Pillow`, `matplotlib`
- Dev dependencies: `pytest`, `pytest-xdist`, `ruff`
- Package skeleton at `src/kotewki/` with `__init__.py`, and empty modules:
  `spec.py`, `geometry.py`, `generator.py`, `export.py`, `quantities.py`
- `tests/` with `conftest.py` exposing fixtures: `spec`, `model`, `published`, `glb_path`
- `justfile` (or `Makefile`) with targets: `build`, `test`, `validate`, `viewer`
- `.gitignore` — ignores `build/` **except** `tests/golden/`
- `git init` + initial commit

## Notes

Use **`trimesh` + `manifold3d`** for solids and boolean operations, not `build123d`.
Rationale: window/door cutouts are boolean subtraction of boxes from wall slabs.
`manifold3d` is fast and robust for that, and avoids pulling in the OCP/OpenCascade
dependency chain, which is a heavy and fragile install for no benefit at this
geometric complexity.

Deliberately **not** using IFC/IfcOpenShell. It would give quantity takeoff for free, but
we would inherit its area-measurement conventions — and given the unresolved
PN-ISO 9836 vs PN-70/B-02365 question (T15), we need explicit control over which wall
faces we measure to, so we can flip the convention and see which one reconciles.

## Acceptance criteria

- `just test` runs and reports zero collected tests without erroring
- `uv sync` completes from a clean checkout
- `python -c "import kotewki, shapely, trimesh, manifold3d"` succeeds
- `ruff check .` passes
