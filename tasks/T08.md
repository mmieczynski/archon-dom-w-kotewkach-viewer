# T08 — Test 2: room areas vs published table

**Depends on:** T07 (geometry kernel) · **Parallel with:** T09, T10

## Goal

`tests/test_room_areas.py` — the checksum over the transcribed dimensions, and the single
most informative test in the suite.

## Why this works

The published room areas are an **independent constraint** on the dimensions. 14
ground-floor areas plus 4 attic figures give ~18 scalar equations over roughly 50
dimension parameters. Underdetermined in the abstract — but every dimension participates
in at least one room, so a typo anywhere breaks at least one assertion. A self-consistent
wrong transcription that preserves every area simultaneously is vanishingly unlikely.

## What to implement

```python
def test_room_areas(model, published):
    for room in model.rooms:
        computed = room.polygon.area
        rel = abs(computed - room.published_area) / room.published_area
        assert rel < 0.01, (
            f"{room.name} ({room.level}): computed {computed:.2f} m², "
            f"published {room.published_area:.2f} m², off by {rel:.1%}"
        )
```

Tolerance ±1%. Attic rooms must go through `usable_area_sloped()`, not raw floor area.

### Second constraint: floor area (powierzchnia podłóg)

Where `floor_area_m2` is present (the parenthesised figure on the plans), assert it too —
against the **raw floor polygon**, with no height banding applied. This is a genuinely
independent equation per room and it disambiguates the two failure causes that otherwise
look identical:

- floor area **passes**, usable area **fails** → the banding rule is wrong (1.4/2.2 m
  thresholds, or the roof geometry feeding them). Geometry is fine.
- **both** fail → the floor polygon itself is wrong.

Most valuable on attic rooms, where banding does the most work.

## The diagnostic report — the real deliverable

A bare pass/fail is not enough. Emit a summary table on failure and make the **failure
pattern** legible, because the pattern tells you the cause:

- **Uniform offset across all rooms** → wrong finish allowance. Do **not** chase
  individual rooms. Hand off to T15. **Expect roughly +2–4% before the finish allowance is
  applied** — that is the known signature of measuring to raw structure instead of
  *w świetle ścian*, and 20 mm per face is the value T03's evidence points to.
- **Single room off** → a real geometry error in that room.
- **All rooms on one level off, other level fine** → level-specific error: wrong
  partition thickness, or the attic banding rule misapplied.
- **Attic off, ground fine** → suspect the height-banding rule before the geometry.

Implement this as an explicit classifier:

```python
def classify_failures(results) -> Literal[
    "uniform_offset", "single_room", "level_specific", "attic_banding", "scattered"
]
```

and print its verdict in the failure output. `"scattered"` (many rooms off by differing
amounts, no pattern) means transcription is broadly wrong — go back to T04/T05, do not
attempt individual fixes.

## Also implement

`just validate --measure-to=structure` and `--measure-to=finish`, running the whole
comparison under both conventions and printing which produces a lower aggregate error.
This is T15's primary evidence, so build it here and let T15 consume it.

## Hard rule

**Never loosen the tolerance to make this pass.** A failing area assertion is a finding
to report, not an obstacle to route around. If ±1% genuinely cannot be met after the norm
is resolved, that is a result worth reporting — it means the published table and the
plans disagree, which is a real and interesting fact about the source material.

## Acceptance criteria

- Per-room comparison with a readable failure table
- `classify_failures` implemented and unit-tested on synthetic failure patterns
- Both `measure_to` conventions runnable from the CLI
- Attic rooms routed through the banding rule
